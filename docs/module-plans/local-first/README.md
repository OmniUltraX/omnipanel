# 本地优先

第 1 节的首次导航已经在应用里。第 2 节的按路径同步已经接上：日常不再推 `modules/latest.json`，会话一条一个文件，不再裁条数。两边都有数据时，同步前会先问认领方式。连接和数据库连接上的创建设备已经是只写一次的字段。其余会同步的记录在写出仓库文件时带上同一字段。自带 S3 的配置在团队管理里。点「抄到这个桶并开始使用」之后，对象才改走那个桶；没抄完之前同步仍走我们的桶。官方桶列不出对象，远端旧块清不掉。自己的桶可以列出并删除。

分四块做：先让本机能用，再换同步协议，存储从第一天就分成「我们的桶」和「用户自己的 S3」，异地组网沿用现有 Headscale，并给会同步的资源加上创建设备字段。

固定的资源和配置都进仓库。运行中产生的记录、窗口摆放、还没进保险库的私钥文件，留在这台电脑。

## 1. 个人空间与首次导航

### 要解决的事

启动现在被登录挡住。没有 token 就停在登录页（微信 / GitHub / 邮箱）。订阅文案已经写了「无需登录即可使用」，数据和连接其实也在本机 SQLite 和钥匙串里。

新用户第一次打开就能用。登录是以后把这份数据交到账号上的可选项。

### 第一次打开

只看完成标志。没弹出过就出现，不管这台电脑上已经有没有连接、有没有登录。走完或跳过登录之后才写完成标志。已有连接或已登录的人，这次仍会看到导航。

```
打开应用
    │
    ├── 导航已经完成 → 启动画面 → 工作台
    │                    有 token 才后台拉仓库，失败不挡进门
    └── 还没弹出过 → 全屏导航
                     ① 欢迎
                     ② 空间名称，默认「我的空间」
                     ③ 本机已有的连接（没有就跳过）
                     ④ 登录，或「只在这台电脑使用」
```

不问主题、语言、数据目录。主按钮用 `WorkbenchActionButton`。登录一步复用现有的微信 / GitHub / 邮箱，并在这一步展示存储声明（见第 3 节）。跳过登录则不出现这段声明，因为没有数据离开本机。

第 ③ 步只列出真扫到的来源，默认勾选，可以取消：

- SSH：已有的 `~/.ssh/config` 导入
- 数据库：已经落地的 Navicat 导入；没装就不出现
- Docker：探测到本机 Engine 才出现

导入写成普通连接，不测试、不拨号。私钥仍是原来的文件路径，不把文件内容写进保险库。主机名能推断出 `prod` 的，只打环境标签，导航期间不连那台机器。

完成标志写在 `omnipanel-store`，不写 localStorage。

### 个人空间

同一账号的所有设备共用一个个人空间。设备不是空间。设备 id 只标明哪台电脑正在写入、谁拿着同步锁。设备 id 写在应用数据目录里。

登录前，本机有一个临时个人空间。会同步的记录从这一天起就带 `space_id`，值为这个临时空间的 uuid。只有一个空间时不显示切换器，整库仍是这一份空间。出现第二个空间时不用再回填。

空间不是工作区。工作区的名称、说明、标签要同步。窗口位置、独立窗口还是内嵌、当前打开的标签，留在这台电脑上。

用户另外上传了一个空间，或账号里已有协作团队时，才显示切换器。另一个空间在服务端是另一个团队 id：自己的仓库、自己的存储位置、自己的一张网。协作团队同样是另一个空间，成员签出同一份，不在每台设备上再复制一份。

### 什么进仓库

固定的资源和配置都进。路径见第 2 节。每条会同步的资源带只写一次的 `originDeviceId`。

资源：

- 全部连接种类：SSH、数据库、Docker、面板、云厂商账号、协议、文件、服务
- 保险库里已有的密码和密钥
- 应用内生成或导入进保险库的 SSH 密钥（记录、公钥、保险库里的私钥）
- 知识库正文、修订，以及 `knowledge/assets/{id}/` 里的附件
- HTTP 已保存请求、集合、环境
- 会话
- 侧栏节点、首页自定义面板
- 工作区的名称、说明、标签
- 工作流定义和步骤
- 待办清单、任务、步骤
- 技能正文
- 第三方账号（阿里云、腾讯云、GitHub、GitLab 等）及其保险库密钥
- 已安装插件的 id、版本、来源、设置和状态
- 模型供应商、网页搜索、HTTP 代理；API Key 进保险库
- 应用设置：语言、主题、终端、编辑器、审批白名单、网关开关和网关密钥、知识库检索参数

插件中心的安装包不进仓库，另一台按 id 和版本重新安装。不是从中心来的旁加载插件，把该插件目录放进仓库。

密钥在资源文件里只留 `credential_ref`。明文只出现在 `vault/{ref}.json`，进仓库前加密。

### 什么留在这台电脑

- 窗口位置、内嵌或独立窗口、当前打开的标签
- 还没进保险库的私钥文件。连接记录会同步；路径在这台电脑不存在时，提示「私钥不在这台电脑」，不让整次同步失败
- 设置里指向本机磁盘的绝对路径（文件索引目录）
- 打了「只留在这台电脑」的记录。这个标记写在本机，不进仓库。没有标记的记录，之后的自动同步会上传
- 同步冲突历史
- 运行产生的数据：终端历史、SQL 执行和结果、审计、知识库与技能的向量块、文件索引、传输任务、组网状态目录、工作流执行记录、任务中心的运行输出、HTTP 调用历史、AI trace、思源 / 知识源的文件扫描缓存

向量不进仓库。知识库正文到了另一台之后，在那台电脑上重建。

打开仓库用的 S3 访问密钥不放进仓库正文。它和空间密钥同一份加密包裹传递，到达后进本机钥匙串。见第 3 节。

### 以后登录

登录是把本机临时空间交到账号上，不另起一份数据。

| 情况 | 结果 |
|---|---|
| 本机还没有自己的数据，账号上已有个人空间 | 加入，把仓库签出到本机。不新建第二个空间 |
| 本机已经有数据，账号上还没有个人空间 | 本机这个临时空间成为账号的个人空间，上传第一份索引。空间 id 沿用本机原来的 uuid。这台电脑是源头，不向其他设备要密钥 |
| 两边都已经有数据 | 先问。默认「并进我的空间」。另两个选项是「只留在这台电脑，不上传」和「作为另一个空间上传」 |
| 用户要把这台电脑分开存放 | 选「作为另一个空间上传」。服务端新建一个团队 id，之后出现在切换器里 |

「只留在这台电脑，不上传」给这批已有记录打上本机标记。之后新建的、没有这个标记的记录，仍会进当前空间。

加入已有空间之后，本机临时空间的 id 退役，改挂到账号空间的 id 上，记录的 `space_id` 跟着改。密钥换成这个空间的密钥，第二台不自己再生成一把。加入或认领成功后提示导出 `.key`。

合并按第 2 节的路径规则。不先做差异清单。完成后提示并入了多少条。之后后台同步若把本机一份放进冲突历史，状态上留一条，直到用户看到。

上传或合并失败不删本机数据。登出只清 token，人留在工作台。已登录冷启动在后台同步。认证服务器连不上也进工作台。

重装后如果设备 id 变了，资源上的 `originDeviceId` 仍指向旧设备，内网转发对不上。把原设备 id 文件放回来，或在这台电脑上重新保存那条连接。

### 不做

- 不改阿里云 / 腾讯云工作台的功能。账号和密钥作为配置同步，见上一节。
- 不做局域网助手配对。助手、小程序、设备列表仍在登录之后。
- 不把 `~/.ssh/` 里未导入保险库的私钥文件打进空间。
- 这一期不轮换空间密钥。摘掉设备或移出团队成员，只停止入网和登录态。对方手里已有的密钥还能解开仓库。要作废得以后换密钥并重加密。
- 所有持有密钥的设备都丢了、又没有导出 `.key`，密文无法恢复。
- Web 版用同一套规则，库在服务器磁盘上。界面要标明这是那台服务器的本地空间。一台服务器同时给多个账号用，不在这份方案里。

### 待确认

- 除 Navicat 外要不要扫 DBeaver / DataGrip。眼下只接已经落地的导入器。

## 2. 同步：按思源的数据仓库来

### 要解决的事

每次改一条连接，都会把本机全部连接、数据库、知识库、HTTP、SSH 密钥、保险库密文和整段侧栏 JSON 打进 `modules/latest.json`，加密后覆盖同一个对象。会话另覆盖 `ai-conversations/latest.json`，还被裁成最多 80 条、每条 120 条消息。

拉取时某个分类只要远端非空，本机该分类里快照没有的 id 会被删掉。所以两台电脑各改各的连接，后上传的整包会吃掉另一台的修改。

思源笔记已经把这件事做成了可运行的产品，同步组件是 [dejavu](https://github.com/siyuan-note/dejavu)。思路拿过来，不拷他们的代码。思源仓库是 AGPL，拷进本仓库会把分发义务带进来。在 Rust 里按同样的数据模型自己写。

### 他们实际在做什么

本地笔记仍是明文文件。要同步时，先为这些文件做一份数据仓库：

- 文件按内容切成块，块的 id 是内容的哈希。相同内容只存一份。
- 一份索引列出当时所有文件，以及每个文件由哪些块组成。
- `refs/latest` 指向最新索引。
- 上传前用本地仓库密钥做 AES。密钥只在设备上，导入到第二台才能解开。
- 云端只收仓库里缺的那些块和索引，不是整份笔记再传一遍。
- 存储后端可换：官方云、S3、WebDAV、本地目录。官方云是他们的付费点，S3 是用户自己的桶。

合并时先记住上次同步到的那份索引。本地相对它的增删，和云端相对它的增删，按文件路径比：

- 只有一边改过的路径，并进来。
- 同一路径两边都改过，算冲突。工作副本用这一轮云端的版本，本机那份放进同步历史，不静默丢掉。
- 同步开始时抢一把云端锁，约 30 秒续期、65 秒算超时，避免两台同时上传。锁减的是撞车概率，不是自动合并。

他们比较文件时用的是路径加修改时间（精确到秒），时间相同就当成没变。这个细节不拿。我们用块 id（内容哈希）判断变没变，避免两台时钟差一秒就把相同内容当成冲突，也避免同一秒里内容变了却被当成没变。

### 我们怎么套

一条记录一个路径。路径用记录 id。改名只改文件内容，不会变成删一条再加一条。工作副本仍是现在的 SQLite 和钥匙串；这些文件是同步用的检出，由 store 在写入时更新。打了「只留在这台电脑」的记录不写出文件。

```
空间数据/
  connections/{id}.json       全部连接种类
  databases/{id}.json         库连接仍单独成表时使用；与 connections 同 id 不写两份
  vault/{ref}.json            密码和密钥的明文只在进仓库前出现
  sshkeys/{id}.json           名称、指纹、公钥；私钥在 vault
  knowledge/{id}.json
  knowledge/{id}/assets/…     附件
  http/requests/{id}.json
  http/collections/{id}.json
  http/environments/{id}.json
  conversations/{id}.json
  tree/{id}.json              侧栏节点
  panels/{id}.json            首页自定义面板
  workspaces/{id}.json        名称、说明、标签；不含窗口位置和打开的标签
  workflows/{id}.json         定义和步骤
  todos/{id}.json
  skills/{id}.json            正文；不含向量
  accounts/{id}.json          第三方账号；密钥在 vault
  plugins/{id}.json           安装记录、设置、状态
  plugins/{id}/pack/…         仅旁加载的插件目录
  ai/providers.json
  ai/web-search.json
  ai/http-proxy.json
  settings/app.json           应用设置；不含本机绝对路径和窗口几何
```

云端目录（我们的 OSS 或用户的 S3，布局相同）：

```
repo/
  indexes/…          一份索引一个对象
  objects/ab/…       加密后的块，按哈希前两位分目录
  refs/latest        指向最新索引。这一期只留这一份，云端不能找回误删
  refs/lock          同步锁
```

未改过的文件，块 id 不变，不再上传。先上传缺的块，块都在了再改 `refs/latest`。上传中断不会把仓库指到一套不完整的块上。

两台各改各的路径，两边都留下。同一路径两边都改过，工作副本取云端这份，本机这份放进这台电脑的冲突历史。同一路径一边删了、一边改了，保留改过的那份，删除不生效，删的一侧记进冲突历史。冲突历史不上传，其他设备看不到。不做成字段级合并。

一个会话一个文件，去掉现在的 80 条会话、每条 120 条消息的裁剪。第一次认领因此可能很大。

未登录不建云端仓库。哪台电脑认领、何时询问合并，见上一节的表。云端已有 `refs/latest` 时按路径合并，不覆盖整个空间。

旧的 `modules/latest.json` 和会话整包在仓库写成之后停写。第一台升级的设备把旧快照拆成上述文件，打成第一份索引。更老的客户端提示升级，不再回推旧快照。旧快照里没有的资源（工作流、待办、技能、插件、模型供应商等）只从本机库补进这第一份索引。

加密仍是每空间一把本地密钥。助手和小程序不读这个仓库。`env_tag=prod` 可以出现在连接文件里，同步不向那些主机发命令。

### 先后

1. 已落地。保存后的自动同步会调用 `local_space_sync`：未登录只重写本机 `space/` 和 `repo/`。重写时只替换库里有的记录，数据库连接、保险库和这次没带上的布局文件留在检出里。已登录时按路径和上次同步的索引合并，冲突用云端版本，本机那份放进 `repo/conflicts/`，不上传。块先加密上传，再改 `refs/latest`。旧 `modules/latest.json` 只在云端还没有仓库时补本机没有的路径。会话一条一个文件，不再裁成 80 条或每条 120 条消息；旧 `ai-conversations/latest.json` 只在仓库里还没有 `conversations/` 时补一次。远端块清理要能列出对象。官方 OSS 凭证列不了，所以官方桶上的旧块留着；自己的 S3 可以列出并删除。本机块会清理。工作流、待办、技能、第三方账号、知识库历史和附件、模型与应用设置会写回本机。旁加载插件目录进仓库，插件中心的安装包不进。
2. 已落地。上传缺的块，按索引合并。两边都有数据时，同步前先问一次：并进我的空间、只留在这台电脑，或作为另一个空间上传。只留本机的那批记录写在本机，不进仓库，也不会被检出删掉。另建空间会先复制当前目录再切过去。
3. 锁会写 `refs/lock`，约 65 秒过期。同一台电脑可以续。冲突历史在本机。本机不再引用的块会删。云端块要等能 List 再删。
4. 日常推送已停止写 `modules/latest.json`。第一台同步时，旧快照里本机没有的路径补进第一份索引。更老的客户端如果还在推整包，不会再被这个客户端回推。

对象放在哪个桶见第 3 节。桶只决定 Put / Get / List 打到哪，索引和块的格式不变。

### 待确认

- 冲突历史留在本机、不进仓库。出现在那条资源旁边，标成冲突。用户自己丢掉这份，或在资源上改、删。不另做一页冲突历史。

## 3. 加密声明与自带存储

### 要解决的事

登录之后，空间的密文要有地方放。放在我们的 OSS 上，流量和容量是我们的成本。这个口子现在就要留出来：默认可以用我们提供的存储，用户也可以换成自己的 S3。以后对我们这份存储收费，不改变同步协议。

登录当时就要把边界说清楚，让人敢把连接和密码交上来同步。

### 登录时看到的声明

出现在导航第 ④ 步和用户中心的登录处，跳过登录的人看不到，因为没有上传。文案按这个事实写，不写「我们什么都看不到」：

- 离开本机的同步数据，先用这台设备上的 `sync_key` 加密，再上传。
- 我们的服务保存的是密文。连接内容、密码、会话正文、模型密钥，服务端解不开。
- 服务端看得到的是账号、设备、团队关系，以及对象的键名、大小、上传时间。这些是存储和在线状态所必需的。
- 密钥不上传明文。换设备时走设备之间的加密传递，或用户自己导入的 `.key` 文件。
- 助手另有一条通道。`overview.json` 是明文，只有各模块条数和设备 id。连接、密码、会话正文不在这份明文里。助手不读空间仓库。

用户点登录，即表示看到了这段说明。不另做一页协议墙。以后文案可以改短，这五条事实不改。

### 存储放哪

每个已绑定的空间有一个存储位置。位置记在账号的这条空间（团队）记录上，这样别的设备找得到桶：

| | 我们提供的存储 | 用户自己的 S3 |
|---|---|---|
| 谁出容量和流量 | 我们 | 用户 |
| 对象放哪 | 现有 `team_sync/{teamId}/repo/` | 用户桶里的同一套 `repo/` |
| 账号上记什么 | 「用我们的桶」 | endpoint、bucket、区域。不记访问密钥 |
| 凭证从哪来 | `POST /api/teams/{id}/oss/sts` | 跟空间密钥放在同一份加密包裹里；用户也可以在新设备上再填一次 |
| 密钥放哪 | 不下发到业务库 | 到达后只进本机钥匙串 |
| 以后 | 可以按容量或团队做成付费项 | 不占我们的存储成本，不作为收费点 |

访问密钥若只写在仓库正文里，另一台在打开仓库之前拿不到它，会打不开桶。所以它不进 `repo/`，和空间密钥一起传递。

默认是我们提供的存储。配置入口在团队管理的「存储」页，不放在别的设置里。用户可以记下自己的 S3：endpoint、bucket、区域。访问密钥进本机钥匙串，不进仓库，界面也不回传明文密钥。同一空间同一时间只有一个位置。换位置时，本机把仓库里的索引和块写到新位置，旧位置的对象留到用户确认后再删。换的是桶，不是空间，本机数据不动。对象抄完之前，同步仍走我们的桶。账号上的位置在抄写完成后再改，避免另一台还在读旧地址时被指到空桶。

S3 兼容即可：阿里云 OSS、腾讯云 COS、AWS S3、MinIO，只要能按前缀列出对象、按键读写。客户端直接对这个桶做 Put / Get / List，不经过我们的服务器转发正文。

未登录没有存储位置。只有个人空间在本机。存储按空间配，不按账号配：个人空间和协作团队可以一个用我们的桶、一个用自己的桶。

### 和不做的事

- 收费规则、套餐、额度现在不定。先有「用我们的桶 / 用自己的桶」这个开关。
- 助手、小程序如果以后要读摘要，仍走现有助手通道，不从用户的 S3 桶里读空间全量。

## 4. 异地组网与创建设备

### 现状

桌面进程用 `tailscale-rs` 连接我们的 Headscale。每个团队一张网，个人团队是 `omni-team-{团队 id}`。登录后入网，登出摘掉。未登录不入网。另一个空间是另一个团队 id，进另一张网。

`omniserver` 只负责签发入网密钥，不转发 SSH 和数据库流量。设备之间能打通时，流量不经过我们；打不通时才走 DERP，那时才占我们的带宽。在线节点是临时的，退出即消失。同时在线数量以后在发密钥前限制，和存储配额分开。

已经走跳板的：SSH（含文件、连接池）、数据库、远程 Docker Engine 直连、面板 HTTP。Web 版没有 mesh。Docker「分享本机 Engine」是把这台机器的引擎给别人用，不是转发一台内网主机。

「只留在这台电脑」的记录不在网上。登录后的这台电脑仍会加入账号个人空间的那张网。

### 创建设备字段

现在写在 `tags` 里的 `origin:`。改为只写一次的 `originDeviceId`。

连接表和数据库连接已经这么做：保存时如果字段是空的，从 `origin:` 抄一次，然后从标签里去掉。库里已经有值就不再改。拨内网地址时先看字段，没有再看旧标签。知识库、HTTP、会话、工作流、待办、技能、账号、插件这些会同步的文件，在写出仓库时同样只写一次：已有字段或旧标签优先，上一份索引里没有的新文件才标成这台电脑。没有地址的资源只标明来源，不拨号。

会同步的资源都要有。会拨地址的（SSH、数据库、远程 Docker、面板，以及连接表里其他会拨号的种类），另一台电脑连内网地址时用它决定转给谁。没有地址的（知识库、HTTP、会话、侧栏、面板、工作区、工作流、待办、技能、账号、插件、设置）只标明来源，不拨号。

窗口布局、打开的标签、本机绝对路径不同步，不加这个字段。旧 `origin:` 迁进字段后不再当标签写。`creator:` 设备名不另存，界面用设备 id 查当前名称。设备 id 在重装后变了怎么办，见第 1 节。
